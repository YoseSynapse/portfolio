    Back End · Python & SQL

    The half a screenshot can’t show.

    A static host can’t run a server, so this chapter does two honest things: it shows the patterns the dashboard actually runs on, and then it runs real Python, in this page, so you can watch it work.

    Exhibit A — Python service

    import json, sqlite3
from http.server import BaseHTTPRequestHandler

db = sqlite3.connect("hub.db")
db.row_factory = sqlite3.Row

class Hub(BaseHTTPRequestHandler):
    def do_POST(self):
        post = json.loads(self.rfile.read(int(
            self.headers["Content-Length"])))
        if slot_taken(db, post["channel"], post["slot"]):
            return self.reply(409, {"error": "slot taken"})
        db.execute("INSERT INTO posts VALUES (?,?,?,?,?)",
                   (post["id"], post["channel"],
                    post["slot"], post["caption"], "queued"))
        db.commit()
        return self.reply(201, {"status": "queued"})

    The posting dashboard’s shape: a small Python HTTP API over SQLite, with the rotation rules enforced server side, not trusted to the client.

    Exhibit B — SQL

    SELECT channel,
       COUNT(*)            AS posts,
       SUM(published)    AS live_posts
FROM   posts
WHERE  scheduled_for >= date('now', '-14 days')
GROUP  BY channel
ORDER  BY live_posts DESC;

    The two week readout query: what actually went live, per channel, the same shape as the Friday content readouts. Parameterized queries only; user input never touches SQL as text (that’s the injection lesson, applied).
